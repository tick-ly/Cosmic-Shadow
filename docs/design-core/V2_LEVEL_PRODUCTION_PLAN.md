## 最新调整：先做一张完整关卡，再扩展数量

用户反馈：当前关卡太简陋。以下调整优先于后文原始排期；四关表保留为后续内容储备，不作为首轮并行制作目标。

### 1. 问题定义

当前运行时以圆柱表示节点、胶囊表示单位，并用直线连接；适合验证规则，但缺少场景空间、探索内容和任务阶段变化。仅增加节点数量、改颜色或随机摆放建筑，仍未解决关卡体验问题。

本轮调整目标：**节点作为底层战术规则，港区场景作为玩家实际看见、理解和操作的关卡。** 保留俯视战术玩法，不扩成 FPS 或大战略项目。

### 2. 唯一优先样板关：灰港断讯

定位：约 5 分钟的夜间港区潜入与撤离。场景围绕六个有辨识度的区域制作：登陆滩、货柜堆场、巡逻道路、维修区、高台中继站、撤离码头。区域可包含多个战术节点，不把一个圆柱当作一个区域的最终表现。

| 层面 | 必做内容 | 对玩法的作用 |
|---|---|---|
| 地形 | 海岸线、水面、岸堤、高台、坡道及道路 | 定义通行边界与高低层路线；视觉高差与规则同步 |
| 建筑 | 仓库、维修棚、中继站、货柜组及围栏 | 形成区域轮廓、遮挡与入口，而非纯装饰散点 |
| 掩体 | 货柜拐角、矮墙、设备箱 | 在已配置战术位置提供暴露/遭遇修正，并显示其效果 |
| 识别 | 中继塔、港口吊机轮廓、撤离灯标 | 镜头默认视角可辨认目标、方向与出口 |
| 路线 | 正门直穿、仓库绕行、沿岸维修通道 | 在耗时、暴露与技能消耗之间形成不同选择 |
| 敌方压力 | 岗哨、少量固定路线巡逻、可读警戒范围 | 玩家观察后选择窗口；先实现轻量状态机 |
| 可选交互 | 侦察终端、配电箱 | 获取巡逻信息或暂时削弱局部警戒，代价为耗时/预算 |
| 任务阶段 | 接近、侦察、破坏、警戒升级、撤离 | 完成目标后出现有预告的压力变化，避免原路空走 |
| 表现反馈 | 单位沿道路运动、选中描边、合法路线预览、目标响应、警报灯及简短音效 | 行动结果直接可见，减少依赖文字日志 |

场景范围以默认镜头可建立全局认知、数次平移可检查局部为准。先用一致风格的模块化低模资产实现完整空间，不以正式美术或超大地图作为前置条件。

### 3. 三条路线必须有实质差异

- **正门路线**：登陆滩 → 巡逻道路 → 中继站。行程短，但岗哨与巡逻暴露高；适合投入技能快速通过。
- **仓库路线**：登陆滩 → 货柜堆场 → 仓库侧门 → 中继站。行程较长，掩体多，可先操作侦察终端。
- **维修路线**：登陆滩 → 沿岸步道 → 维修区 → 中继站后侧。需要打开维修入口；提供额外操作选择，不强制依赖一次随机技能成功。

前两条路线初始开放；维修入口失败后允许付出额外时间/预算再次处理，或返回其他路线。纯装饰建筑不阻挡已定义的合法路线；阻挡与遮挡必须同时进入规则查询。

目标完成后：先给出警戒升级预告，再调整一组巡逻/警戒区域；码头撤离始终保留至少一条可达路径。若引入路线封锁，须先实现动态可达性验证再启用。

### 4. 修订后的实施顺序

| 顺序 | 工作 | 可检查交付 |
|---|---|---|
| S1 空间灰盒 | 六区域布局、高差、道路、三路线、镜头范围；先替换主视图中的圆柱节点展示 | 一张可走通、有清晰空间结构的港区灰盒场景 |
| S2 行动与遭遇 | 沿路运动、移动期间状态、掩体修正、岗哨/巡逻、可读警戒、统一计时 | 三条路线均能实玩，耗时与风险确有差异 |
| S3 任务内容 | 侦察终端、配电箱、目标操作、警戒升级、撤离与失败反馈 | 一次完整“接近—行动—撤离”体验 |
| S4 表现整合 | 模块化建筑替换、地表材质、水面、灯光、目标标识、音效与简报/结算 | 统一视觉风格且不遮蔽战术信息的样板关 |
| S5 生成与验证 | 将场景布局、预制体、规则节点与引用纳入可重复生成流程 | 实际 Unity 场景、依赖资产、重建入口与验证记录 |
| S6 内容扩展 | 样板关验收后再制作教学、正面突击与侧翼骚扰关 | 用不同空间和目标结构扩展，而不是复制布局换名称 |

S1 开始前处理 P0 中会阻碍本关的基础错误；L00 保留作轻量回归测试，不优先投入美术。生成器服务于已验证的关卡设计，不先做复杂随机地形系统。

### 5. 新增工程约束

- 增加场景布局配置：区域、建筑/掩体预制体、道路控制点、战术锚点、巡逻路线、灯光和交互物。
- 纯 C# Core 保存逻辑位置、通行/暴露/掩体及遭遇结果；Runtime 表现移动和视野，避免以渲染对象颜色代替规则。
- 明确定义移动开始、进行中、抵达与取消；抵达前不触发目标交互，移动中避免重复派发行动。
- 视觉路径与规则路径使用同一份布局来源；校验单位不穿过仓库、不穿墙、不越过未开放入口。
- 生成物包含场景空间与交互绑定，不止输出节点图 SO；手工调好的布局先保存为配置再重建，避免丢失设计。

### 6. 样板关验收门槛

- [ ] 隐藏调试连线后，仍能辨认六区域、主要道路、任务目标和撤离方向。
- [ ] 三路线均实走验证，记录耗时、警戒、技能与预算消耗；至少两条路线在代价上存在权衡，而非一条全面占优。
- [ ] 掩体、侦察、配电箱至少各有可观察且可测试的规则作用。
- [ ] 警戒来源和后果有预览/反馈；关键目标不会被镜头遮挡或界面盖住。
- [ ] 目标完成后确实进入不同的撤离阶段，变化有提示、路径仍有解。
- [ ] 从选关到结算、失败重开、重复生成均有实测记录；首轮至少完成三条路线各一次通关。
- [ ] 固定测试机与显示设置后记录帧时间和操作响应，再确定性能门槛；未测量前不宣称稳定帧率。

本轮首要交付由“四张节点地图”调整为：**一张具有地形、建筑、路线选择、敌方压力和任务阶段的完整样板关，以及可重建它的生成流程。**

### 需明确的策划口径

1. **时间**：旧短任务方案同时出现“无硬倒计时”和 300 秒配置；首批按明确的 V2 MVP 规格保留超时失败。建议正式关默认 300 秒，教学关 420 秒。动态压力取代倒计时留到后续版本。
2. **计时实现**：建议统一为实时时钟，取消移动额外扣时；行动动画/行动耗时由同一时钟计量。战术暂停同时冻结任务时钟及行动推进。
3. **债务**：单位债务与节点局部债务是两个独立概念。后者若启用，单独采用原案 0–100 范围，禁止直接套用单位债务的 500/800 风险阈值。
4. **技能语义**：当前“预算直觉”样例也能增加目标进度。扩展时区分侦察、破坏、支援能力，侦察技能仅提供信息；目标仅接受匹配的交互。
5. **任务目标**：通用胜利继续要求目标完成及存活单位撤离。坚守、运载护送等不同胜负条件暂留后续；本轮正面任务选择“攻克目标后撤离”。

## 四、首批四关设计

以下名称、数量和数值是本计划新增提案，不是原策划已经锁定的内容。节点数计入出生点、目标点和撤离点；正式关时长目标约 5 分钟，实际时长由实玩记录验证。

| ID | 关卡 | 类型/规模 | 单位建议 | 目标与核心抉择 | 依赖 |
|---|---|---|---|---|---|
| L00 | 中继站演练 | 教学，5 节点 | 1 名行动员 | 到目标推进 2 点后撤离；学习技能风险和目标完成后仍需撤离 | P1；现有单目标框架 |
| L01 | 灰港断讯 | 潜入，8 节点 | 1–2 名行动员 | 破坏中继站，进度 3；短路高警戒、长路低压力 | P2；节点遭遇/警戒规则 |
| L02 | 海峡破口 | 正面突击，10 节点 | 陆军队伍、行动员、空中支援 | 先破坏护盾节点，再攻克沿海堡垒，最后撤离 | P3；顺序目标、守点遭遇、空军范围 |
| L03 | 潮汐截击 | 侧翼骚扰，12 节点 | 快艇队伍、行动员 | 破坏两个分散通信节点，顺序自选；海路与陆路分工 | P3；多目标、海军资产、海陆通行 |

### L00：中继站演练

- 节点：前进基地、断裂山脊、潮汐通道、中继站、撤离点。
- 拓扑沿用样例：基地—山脊—中继站—撤离点；基地—潮汐通道—中继站；潮汐通道—撤离点。
- 初始提案：420 秒、警戒上限 5、目标进度 2。提供足够预算尝试至少一次失败后的补救。
- 引导顺序：选单位、看路线、移动、阅读成功率与反噬、完成目标、撤离。
- 特别验收：提前到撤离点不直接获胜；目标完成且已有存活单位位于撤离点时，按现有规格判胜。

### L01：灰港断讯

- 节点：入口、岗哨、货场、暗渠、海堤、维修站、中继站、撤离码头。
- 主路：入口—岗哨—货场—中继站—撤离码头。
- 绕行：入口—暗渠—海堤—维修站—中继站；海堤—撤离码头形成退路。
- 所有常规步行路线均使用陆路，沿海节点仍保持陆军可达；地名“暗渠”本身不代表海军专用路线。
- 初始提案：300 秒、警戒上限 3、目标进度 3。岗哨的警戒代价须来自规则，不只是危险度标签。
- 特别验收：失败一次后的补救路线仍存在；维修站本轮仅作为绕行节点，不预设未实现的回复功能。

### L02：海峡破口

- 节点：集结点、山口、掩体、前哨、侧翼高地、护盾站、沿海道路、堡垒、直升机平台、撤离点。
- 正面：集结点—山口—前哨—护盾站—沿海道路—堡垒—撤离点。
- 侧翼：集结点—掩体—侧翼高地—护盾站；侧翼高地—直升机平台—沿海道路。
- 目标依赖：护盾站完成 → 堡垒目标解锁 → 全部目标完成后撤离。空中支援提供机动或遭遇帮助，仍遵守目标依赖。
- 初始提案：300 秒、警戒上限 5、两个目标分别需要 2/3 点。地图布局需满足空军范围与陆路路线测试。
- 特别验收：护盾未解除时对堡垒操作有明确反馈且不推进进度；敌方节点有实际守点结算，但不引入复杂 AI。

### L03：潮汐截击

- 节点：出发港、内湾、浮标、水道、外海、东通信站、西通信站、海岸入口、山径、道路枢纽、会合港、撤离港。
- 海路：出发港—内湾—浮标—东通信站—水道—外海—西通信站—会合港—撤离港。
- 陆路：海岸入口—山径—道路枢纽—西通信站；道路枢纽—东通信站；道路枢纽—会合港。
- 出发港、两个通信站、会合港、撤离港为沿海；内湾、浮标、水道、外海为水域；其余为陆地。行动员从海岸入口出生，快艇从出发港出生。
- 初始提案：300 秒、警戒上限 4、两个目标各需 2 点，顺序不限；给快艇或同行单位配置适配目标的行动能力。
- 特别验收：目标分别计数且完成后禁止重复刷进度；至少一条合法作战与撤离路径通过领域校验。桥梁破坏及永久断路留待后续动态拓扑版本。

## 五、关卡生成器的强制交付要求

### 生成方式

先做“设计模板驱动的确定性生成”，而不是无约束随机地图。后续再引入种子控制的有限变体；变体只在规则校验通过后写入关卡包。

输入至少包括：关卡 ID、版本、类型、简报、节点/路线、单位出生点、目标与前置关系、撤离点、时限、警戒阈值、技能与预算配置。

### 输出

拟新增统一生成入口 `Shadow/V2/Generate Level Pack`，保留旧样例生成入口作为回归工具。新入口尚未实现。

每关生成：

1. 一个 `NodeMapSO` 地图资产。
2. 一个 `TacticalMissionSO` 任务资产（多目标阶段扩展兼容字段）。
3. 一个 `MissionBootstrapConfigSO` 启动配置。
4. 一个绑定正确配置的可进入场景；共享单位/技能资产可复用。
5. 所有新增 Unity 资产对应的 `.meta`。
6. 一条选关目录记录，以及关卡 ID、生成版本、内容摘要、校验结果组成的清单。

拟定关卡输出目录：`UnityProjectV2/Assets/_ProjectV2/Generated/Levels/`。

生成报告拟放：`docs/validation/`。这些是计划路径，本次未生成游戏资产或报告。

### 可重复生成与保护

- 同一模板生成相同玩法数据，不产生编号后缀副本；忽略编辑器自身时间等非玩法差异。
- 尽量更新已有资产，保持 GUID 和外部引用稳定。
- 仅管理明确标记的生成目录；手工策划资产置于独立目录。
- 先校验再写盘；遇到错误保留上次有效版本并报告关卡 ID、字段和原因。
- 合并构建场景列表，保留已有条目；现有样例工具整体替换列表的行为应收口。
- 保存场景前检查未保存编辑，避免批量生成干扰当前工作场景。

## 六、测试与验收

- [ ] Core 独立编译；分层及 asmdef 引用符合 V2 工程规则。
- [ ] 现有与新增 EditMode 测试实际执行并保存结果。
- [ ] 节点/单位/目标 ID 唯一，连线端点存在，无重复边与意外孤点。
- [ ] 按实际参战单位的领域、技能、范围检查出生 → 目标 → 撤离，而不是仅判断地图整体连通。
- [ ] 多目标前置关系无环且可完成；初始预算支持至少一条全成功通关方案。
- [ ] 以固定技能结果验证胜利、超时、警戒触顶、全员阵亡、预算不足、冷却和目标未解锁等分支。
- [ ] 明确同一时刻失败阈值与胜利都满足时的判定顺序，默认保持现有失败优先。
- [ ] 关卡路线有解不等于每局随机技能必胜；记录失败后的补救空间与实玩胜率，不作必胜承诺。
- [ ] 重开恢复时间、进度、单位、预算、债务、冷却及 UI；快速换关清除旧对象和事件。
- [ ] 连续生成两次，关卡数量、GUID、引用与玩法数据稳定，其他场景/资产保持原状。
- [ ] 每关至少完成一次真实 Play Mode 胜利及一次失败后重开，记录耗时、路线和日志。
- [ ] 正式关以约 5 分钟体验为调优目标；分别记录墙钟时间与游戏时钟，避免用配置值代替体验证据。
